# Постоянный ключ подписи

Android устанавливает обновление поверх установленного приложения **только** если оно
подписано тем же ключом. Если ключ меняется, обновление отклоняется («Приложение не
установлено»), и его можно поставить лишь после удаления приложения — вместе со всеми
проверками и архивом. Поэтому ключ подписи должен быть один и тот же навсегда.

| Параметр | Значение |
| --- | --- |
| Отпечаток сертификата SHA-256 | `6ceb4c2eeb3f3d5a22ea325fb68923c713bd8ac012a3706c4a8ce6369183d032` |
| Псевдоним (alias) | `backup-control` |
| Формат | PKCS12, RSA 2048, срок действия до 2056 года |
| Файл ключа | [`release-key/backup-control-release.p12`](release-key/backup-control-release.p12) |
| Пароль | [`release-key/password.txt`](release-key/password.txt) |
| Публичный сертификат | [`docs/release-certificate.crt`](docs/release-certificate.crt) |
| Закреплённый отпечаток | [`docs/release-fingerprint.txt`](docs/release-fingerprint.txt) |

Ключ **намеренно опубликован** в репозитории, чтобы любая сборка — в том числе в форке
или на другом раннере — подписывалась одинаково и обновления никогда не ломались.
Подробности и оценка рисков: [`release-key/README.md`](release-key/README.md).

## Как это работает в CI

1. `Prepare persistent release signing key` — берёт ключ из секретов
   `ANDROID_KEYSTORE_*`, если они заданы, иначе из `release-key/`.
2. `Test and build signed release` — собирает подписанный APK и **сверяет его
   сертификат** с `docs/release-fingerprint.txt`; несовпадение валит сборку.
3. `Verify signature and signing-key continuity` (job `publish`) — повторная проверка
   перед публикацией.
4. `Publish GitHub Release` — дополнительно проверяет, что `versionCode` APK совпадает с
   тегом `v1.0.<run>`, из которого приложение-обновлятор берёт номер версии.

Если секреты не заданы и папки `release-key/` нет, workflow собирает только debug-APK и
предупреждает: ставить его поверх прошлых сборок нельзя, данные не сохранятся.

## Если ключ нужно сменить

1. Сгенерировать новый PKCS12 и заменить `release-key/backup-control-release.p12`,
   `release-key/password.txt`, `docs/release-certificate.crt` и
   `docs/release-fingerprint.txt` **одним коммитом**.
2. Понимать последствие: у всех, кто уже установил приложение, обновление потребует
   переустановки с потерей локальных данных.

## Если ключ потерян

Обновление поверх установленного приложения станет невозможным. Держите копию файла
ключа и пароля в менеджере секретов и в офлайн-бэкапе.
