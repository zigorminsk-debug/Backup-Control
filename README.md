# Backup Control

Android-приложение для **ручного еженедельного контроля резервных копий**. Работает локально, без аккаунта и сервера. Оно не выполняет резервное копирование и не проверяет его автоматически: пользователь отмечает результаты в чек-листе.

## Возможности

- Выберите день недели и время проверки. В назначенное время приходит уведомление, а отметки чек-листа сбрасываются для новой недели. Если приложение или телефон были выключены, новая неделя определяется при следующем запуске.
- Добавляйте, переименовывайте и удаляйте пункты. Начальные три пункта — примеры, их можно изменить под свою инфраструктуру.
- Для каждого пункта можно назначить отдельное напоминание об ошибке с датой, временем и описанием. Оно сохраняется при смене недели; после решения ошибки его можно закрыть.
- Напоминания восстанавливаются после перезагрузки, обновления приложения и смены времени/часового пояса. На Android 13+ разрешите уведомления, на Android 12+ — точные напоминания. Если точные сигналы не разрешены, Android может доставить уведомление с задержкой. Энергосберегающие ограничения производителя также могут задерживать доставку.
- Приложение автоматически проверяет GitHub Releases при запуске и примерно раз в 12 часов в фоне (фактический интервал определяется Android). Новую версию скачивает автоматически, проверяет имя пакета, номер версии и сертификат подписи. Android **обязательно попросит пользователя разрешить установку из этого источника и подтвердить обновление**: обычное приложение не может устанавливать APK бесшумно. Данные при обновлении поверх сохраняются.

Требуется Android 6.0 или новее. Интернет нужен только для обновлений.

## Установка

Скачайте `Backup-Control.apk` из [последнего выпуска](https://github.com/zigorminsk-debug/Backup-Control/releases/latest) и откройте его на телефоне. При первом запуске разрешите уведомления и точные сигналы через подсказки в приложении. Установка первого APK и дальнейших обновлений требует подтверждения в Android.

**Debug-артефакт GitHub Actions предназначен только для проверки сборки.** Он подписан временным ключом CI и не подходит для обновления поверх постоянного релиза.

## Сборка и постоянный ключ подписи

GitHub Actions собирает приложение и запускает тесты при каждом push и pull request. При наличии всех четырёх секретов push в основную ветку публикует подписанный `Backup-Control.apk` в GitHub Releases. Вручную можно запустить workflow с параметром `publish`; он должен уже существовать в основной ветке. Без секретов создаётся только debug-артефакт, релиз не публикуется.

Перед первым релизом владелец репозитория должен **один раз** создать собственный ключ и сохранить резервные копии файла и паролей в надёжном месте. Например, с установленной Java:

```bash
keytool -genkeypair -v -storetype PKCS12 -keystore backup-control.p12 \
  -alias backup-control -keyalg RSA -keysize 4096 -validity 36500
```

Не добавляйте ключ и пароли в репозиторий. В GitHub откройте **Settings → Secrets and variables → Actions → New repository secret** и создайте:

| Имя секрета | Значение |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | Содержимое файла `backup-control.p12`, закодированное в Base64 одной строкой (Linux: `base64 -w 0 backup-control.p12`). |
| `ANDROID_KEYSTORE_PASSWORD` | Пароль хранилища ключей. |
| `ANDROID_KEY_ALIAS` | Алиас ключа, например `backup-control`. |
| `ANDROID_KEY_PASSWORD` | Пароль ключа (для PKCS12 обычно совпадает с паролем хранилища). |

GitHub не позволяет прочитать секреты обратно. **Потеря ключа или паролей сделает обновление поверх уже установленных версий невозможным.** Не заменяйте ключ между сборками. Номер версии задаётся номером запуска workflow; формат релиза `v1.0.<номер>` и имя файла `Backup-Control.apk` используются встроенным механизмом обновления.

Для локальной проверки при наличии Android SDK и JDK 17: `./gradlew testDebugUnitTest assembleDebug`.
