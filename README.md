# Backup Control

Android-приложение для контроля регулярности резервного копирования: недельный чек-лист,
архив выполнений, напоминания об ошибках и автообновление прямо из GitHub Releases.

## Возможности

- **Чек-лист проверок** — свои пункты (серверы, базы, файлы), отметка «проверено».
- **Расписание** — выбранный день недели и время; задачи возвращаются в список с начала
  назначенного дня, а в заданное время приходит уведомление о невыполненных.
- **Архив** — дата и время каждого выполнения сохраняются навсегда, ошибочную отметку
  можно отменить, не теряя историю.
- **Напоминания об ошибках** — отдельный срок и комментарий; не пропадают даже после того,
  как задача ушла в архив.
- **Автообновление** — проверка GitHub Releases дважды в сутки, загрузка и установка только
  после проверки подписи APK тем же ключом, что и установленное приложение.

Все данные хранятся локально (SharedPreferences `backup_control`, резервное копирование
Android включено через `backup_rules.xml` / `data_extraction_rules.xml`).

## Сборка

```bash
./gradlew assembleDebug        # тестовая сборка
./gradlew testDebugUnitTest    # модульные тесты (WeekSchedule, ReleaseRules)
```

Все сборки подписываются одним постоянным ключом из [`release-key/`](release-key/) — иначе
обновление не установится поверх приложения и данные потеряются. Подробности:
[`SIGNING.md`](SIGNING.md).

## CI: GitHub Actions

`.github/workflows/android.yml` на каждый push и pull request:

1. `android` — юнит-тесты и сборка APK. С настроенным ключом собирается подписанный release,
   без ключа — только debug (с явным предупреждением в Summary).
2. `ui-smoke` — реальный эмулятор Android 15: установка, добавление пункта, напоминание,
   архив, возврат задачи по расписанию, фоновые уведомления и обновление «поверх» с тем же
   ключом. Скриншот публикуется артефактом.
3. `publish` — только после успеха обоих job'ов: проверяет подпись и неизменность ключа,
   затем публикует GitHub Release `v1.0.<run_number>` с `Backup-Control.apk`.

Релиз публикуется при push в основную ветку или в любую ветку с `[publish-release]` в
сообщении коммита, а также вручную через `workflow_dispatch` (`publish: true`).
