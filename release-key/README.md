# Постоянный ключ подписи (публикуется осознанно)

В этой папке лежит **единственный** ключ, которым подписываются все сборки
Backup Control:

| Файл | Назначение |
| --- | --- |
| `backup-control-release.p12` | хранилище ключа (PKCS12, RSA 2048) |
| `password.txt` | пароль хранилища и ключа (они совпадают) |

| Параметр | Значение |
| --- | --- |
| Псевдоним (alias) | `backup-control` |
| Отпечаток SHA-256 | `6ceb4c2eeb3f3d5a22ea325fb68923c713bd8ac012a3706c4a8ce6369183d032` |
| Действителен до | 20.10.2056 |

Публичный сертификат и закреплённый отпечаток — в [`../docs/`](../docs/).

## Зачем ключ лежит в репозитории

Android устанавливает обновление поверх приложения только тогда, когда оно подписано
**тем же** ключом. Ключ, который генерируется заново на каждом запуске CI, делает
обновление невозможным: пользователю пришлось бы удалить приложение и потерять
чек-лист и архив. Поэтому ключ зафиксирован в репозитории: любая сборка, в любом
форке, любым человеком подписывается одинаково.

## Что это значит с точки зрения безопасности

- Ключ **публичный**: любой может подписать им APK, который установленное приложение
  примет как обновление. Само приложение скачивает обновления только из релизов этого
  репозитория на GitHub, поэтому для атаки нужно убедить пользователя установить APK
  вручную.
- Ключ нельзя использовать для загрузки в Google Play или для чужих приложений —
  он подходит только для `com.zigorminsk.backupcontrol`.
- **Потеря или замена ключа = потеря данных у всех пользователей**: обновление поверх
  установленного приложения станет невозможным. Резервную копию файла и пароля держите
  в менеджере секретов.

## Как CI использует ключ

Шаг `Prepare persistent release signing key` в `.github/workflows/android.yml`:

1. если в репозитории заданы секреты `ANDROID_KEYSTORE_*`, берётся ключ из них
   (это позволяет сменить ключ без правки репозитория);
2. иначе берётся `release-key/backup-control-release.p12` + `release-key/password.txt`;
3. если нет ни того, ни другого — собирается только debug-APK с предупреждением.

Собранный APK проверяется `apksigner verify` и сверяется с отпечатком из
`docs/release-fingerprint.txt`; при несовпадении сборка падает.
